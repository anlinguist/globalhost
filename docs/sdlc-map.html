    How each kind of change reaches prod

    ChangePath
    App code, config, testsPR → merge → release workflow
    Infra with an IaC provider (GCP, Cloudflare, Neon)IaC in the PR, with a review stack for risky diffs → merge → release applies it
    Vendor setup with no IaC (verify a domain, toggle a setting)Dev: the agent does it through MCP. Prod: an ops: request, your approval, then a trusted executor runs exactly those calls
    SecretsYou set them. Agents only see secret names, plus dev keys injected at the network edge
    Data migrationsExpand (backward compatible) → release → contract in a later PR
    Extension permissions, breaking API, destructive migrations, new dependenciesAlways your explicit approval, at every autonomy level

    What the factory never does

    • Merges its own work, except allowlisted routine classes at L3. Auto-fixes are never auto-merged.
    • Deploys to prod or changes a prod vendor without a merge or an approved ops request.
    • Acts on instructions from anyone but you. Text from others is read as data.
    • Exceeds the per-run, daily or monthly budget. It pauses and asks instead.
